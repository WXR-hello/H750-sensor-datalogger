# IMU 数据记录到 SD 卡（IMU 串口改到 PA9/PA10）

本次改动的目标：

1. **不需要实时给 MATLAB 画图了** —— 删掉 46 字节二进制帧上报；
2. **把数据记录到 SD 卡上**（CSV 文件，FatFs 文件系统）；
3. **IMU 传感器的串口改到 PA9/PA10**（USART1），**之前用的 UART4（PC10/PC11）删掉**。

结果：现在全板只开一个串口（USART1），PC10/PC11 空出来给 SD 卡用（SDMMC1 的 D2/D3）。

---

## 一、接线

| 板上引脚 | 接到哪里 | 说明 |
| --- | --- | --- |
| **PA9** | IWT603 模块的 **RX** | USART1_TX，板子发给模块 |
| **PA10** | IWT603 模块的 **TX** | USART1_RX，模块发给板子 |
| GND | 模块 GND | 必须共地 |
| 3V3 / 5V | 模块 VCC | 按模块要求供电 |

SD 卡直接用板子上的 TF 卡座（J28），**不需要另外接线**：

| 信号 | 引脚 | 信号 | 引脚 |
| --- | --- | --- | --- |
| SDMMC1_D0 | PC8 | SDMMC1_D3 | PC11 |
| SDMMC1_D1 | PC9 | SDMMC1_CK | PC12 |
| SDMMC1_D2 | PC10 | SDMMC1_CMD | PD2 |

### ⚠ 最重要的一条：PA9/PA10 上的 J80 / J81 跳线帽必须拔掉

野火官方《STM32H7 PRO IO 分配表》里写得明明白白：

* **PA9**：接上 **J80** 跳线帽 -> 用板载 USB 转串口（TX）；**拔掉 J80** 才能把这根脚接排针给别的模块用；
* **PA10**：接上 **J81** 跳线帽 -> 用板载 USB 转串口（RX）；**拔掉 J81** 才能把这根脚接排针给别的模块用。

也就是说：**跳线帽装着的时候，PA10 上同时挂着 CH340C 的 TXD**。
CH340C 空闲时把 PA10 拉高，模块的 TX 抢不过它，MCU 就收不到模块的数据 —— LCD 上就一直
显示"无传感器请检查连接"。所以用模块时**必须把 J80、J81 两个跳线帽拔掉**，
并且不要在 CH340C 对应的那个 COM 口上开串口助手（它会往线上灌数据）。

（USB 线插着只是给板子供电的话一般没事，但拔掉跳线帽再试最稳妥。）

注意两点：

* 野火 H750/H743 底板的 **TF 卡座和板载 WIFI 模块共用 SDIO 引脚**，两者不能同时使用。
  不用 WIFI（不装 WIFI 模块）时 TF 卡可以直接用。
* 文件系统：**FAT32 和 exFAT 都支持**（2026-09-25 起打开了 `FF_USE_LFN` 和 `FF_FS_EXFAT`）。
  所以 **64GB/128GB 这类出厂就是 exFAT 的卡可以直接用，不需要格式化**。
  仍然要注意的是：
    * 卡必须是**一个分区**（MBR）的 FAT32/exFAT，不能是 NTFS、也不能是 GPT 分区表；
    * `FF_USE_LFN` 用的是"静态缓冲区"（`User/fatfs/ff.c` 里的 `DirBuf`/`LfnBuf`），
      RAM 多占约 350 字节；
    * 字符编码用的是最小实现（`User/fatfs/ffunicode.c`）：**只保证 ASCII 文件名**，
      卡里带中文名的文件不会被识别（也不会乱码），但我们的 `IMU0001.CSV` 完全正常；
    * Flash 占用从 92KB 涨到约 98KB / 128KB。
* SD 初始化（2026-09-25 晚改）：先用 **1 线模式**认卡并挂载，成功后再用
  `HAL_SD_ConfigWideBusOperation()` 尝试升到 4 线；升不上去就保持 1 线继续用。
  原因是原写法直接按 4 线调 `HAL_SD_Init()`，4 线切换（DAT2/DAT3）失败时整个初始化
  都返回错误，屏幕会显示"SD 认不到卡"，而卡其实已经认出来了。
  1 线 25MHz 约 3MB/s，本工程 10Hz 的数据量完全够用。
  （`User/sd/bsp_sd.c` 里的 `SD_Init()`，另有 `SD_GetBusMode()` 可以查当前是 1 线还是 4 线。）
* **【重要】H7 的 DMA 访问不到 DTCM —— SD 缓冲区必须放 AXI SRAM（2026-09-25 夜）**
  症状：卡能认到、命令全通，但一读数据就失败，FatFs 报 `FR_DISK_ERR`（屏幕显示"SD 读卡失败 1"）。
  原因：HAL 的 `HAL_SD_ReadBlocks()/HAL_SD_WriteBlocks()` 是用 **SDMMC 的内部 DMA（IDMA）**
  搬数据的（HAL 里写 `IDMABASE0` + `IDMACTRL`），而 **STM32H7 的 DMA 访问不到 DTCM
  （0x20000000）**；本工程散列文件默认把所有变量都放在 DTCM，FatFs 的 `FATFS`（含 512 字节
  读写窗口 `win[]`）和 `FIL`（含 `buf[]`）就在里面 → IDMA 写不进去 → 读卡失败。
  解决（三处配合）：
    1. `MDK-ARM/H750XB_Flash.sct`：RW_IRAM2（AXI SRAM）里加 `*(.sd_dma)` 选择子；
    2. `User/sd/imu_sdlog.c`：`s_fs`/`s_file`/`s_line` 加
       `__attribute__((section(".sd_dma")))`，链接后落在 `0x24000120` 起的 AXI SRAM（map 可查）；
    3. `User/sd/bsp_sd.c` 的 `SD_Init()`：`Board_MPU_Config(2U, MPU_Normal_NonCache,
       0x24000000, MPU_32KB)` 把 AXI SRAM 头 32KB 配成 **non-cacheable**
       （SDMMC IDMA 看不到 D-Cache，必须让 CPU 和 DMA 看到同一份数据），
       随后 `SCB_CleanInvalidateDCache_by_Addr()` 清理一次。
  记住这条：以后给这个工程加任何"DMA 搬运"的缓冲区，都不能放在 DTCM。

## 二、SD 卡里存什么

* 文件名：`IMU0001.CSV`、`IMU0002.CSV` ……（8.3 短名，不需要长文件名支持）
  每次上电**新建一个文件**，不覆盖以前的数据；序号依次往后排（最多 9999 个）。
* 表头：`t_ms,roll,pitch,yaw,ax,ay,az,gx,gy,gz,temp`

| 列 | 含义 | 单位 | 小数位 |
| --- | --- | --- | --- |
| t_ms | 上电后的时间 | 毫秒 | 整数 |
| roll / pitch / yaw | 横滚 / 俯仰 / 航向 | 度 | 3 位 |
| ax / ay / az | 三轴加速度 | g | 4 位 |
| gx / gy / gz | 三轴角速度 | 度/秒 | 2 位 |
| temp | 温度 | 度 | 2 位 |

* 记录节奏：**20Hz**（模块每回传一帧角度数据记一行，最快 50ms 一行）。
* 落盘节奏：**每 20 行或每 2 秒**自动 `f_sync()` 一次 —— 突然断电最多丢 2 秒数据。
* 一行大概是这样的：

```text
t_ms,roll,pitch,yaw,ax,ay,az,gx,gy,gz,temp
12345,1.235,-0.742,88.105,0.0123,-0.0046,0.9987,0.12,-0.35,1.07,26.35
```

MATLAB 里直接读：

```matlab
T = readtable('IMU0001.CSV');
plot(T.t_ms/1000, T.yaw);
```

## 三、上电后会看到什么（LCD）

1. 最底下一行先显示 `正在查找传感器`（逐个波特率 4800→921600 找模块，最多几秒）；
2. 找到后显示 `已连接 9600`（把扫到的波特率显示出来，方便排查接线）；
3. 接着挂载 SD 卡、新建 CSV 文件，**标题行显示文件名**（如 `IMU0001.CSV`）；
4. 开始记录后，最底下一行显示 `已存 1234 帧`，数字就是已经记了多少行。

状态行的几个提示：

| LCD 提示 | 意思 | 怎么办 |
| --- | --- | --- |
| `已存 N 帧` | 一切正常，正在记录（N = 已写入行数）| — |
| `SD 认不到卡 n` | 认卡阶段失败 = 卡没被识别（n = HAL 错误码，3 = 命令响应超时）| 重新插紧 / 换卡 / 拔掉 WIFI 模块（共用 SDIO）|
| `SD 卡不是 FAT32` | 卡认到了但挂载不上（FatFs: FR_NO_FILESYSTEM）| 在电脑上格式化成 FAT32（>32GB 的卡 Windows 默认只能格 exFAT，要用工具）|
| `SD 读卡失败 n` | 挂载失败，n = FatFs 的 FRESULT | 先格式化，再不行换卡 |
| `SD 写入失败 n` | 能挂载但建文件/写表头失败 | 卡只读/满/坏了 |
| `无传感器请检查连接` | 没收到模块回包 | 看 PA9/PA10 有没有接反、模块有没有供电 |
| `无SD请检查连接` | 没插卡 / 卡不是 FAT32 | 插卡；在电脑上把卡格式化成 FAT32 |
| `SD读写错误` | 卡掉了 / 写保护 / 接触不良 | 重新插卡，程序会自己重试 |

> 上面这套"分步提示"是 2026-09-25 加的：`User/sd/imu_sdlog.c` 里把失败分成
> 1=认卡、2=挂载、3=建文件三步并记下错误码（`IMULog_GetFailStage/GetFailCode`），
> `main.c` 的 `LCD_ShowSdStatus()` 按这三步显示中文原因，方便一眼定位。

**没插卡也不会死机**：程序每 2 秒重试一次，插上卡后会自动开始记录（文件名接着排）。

### 找不到模块时，标题行会显示诊断信息

没扫到模块时，**标题行会显示 `RX 1234 B9600`**：

* `RX xxxx` = 这个串口一共收到了多少字节；
* `Bxxxx` = 当前正在试的波特率（程序会 4800→921600 轮流试）。

怎么用它判断问题：

| 现象 | 结论 |
| --- | --- |
| `RX 0` 一直不动 | **一个字节都没进来**：接线错（PA9/PA10 接反或没接）、模块没供电、没共地，或者 J80/J81 跳线帽还装着把线占住了 |
| `RX` 一直在涨，但一直是"无传感器" | 有数据进来但没解析出来：波特率对不上（模块被设成奇怪的档位）、数据格式不是标准协议，或者线上有别的设备在抢（CH340C/串口助手） |
| `RX` 有数，标题行 / 状态行显示 `IMU B9600` + `已存 N 帧` | 认到模块了，正在记录 |

另外：**模块是上电后才插上/才上电也没关系** —— 程序每 3 秒会重新扫一次波特率，
认到就自动开始记录（`g_sensorFound` 掉线 5 秒也会自动重扫）。

### 4.4 SD 卡的访问方式（为什么不用 DMA）

> ⚠️ **2026-10-05 更正（重要，先看这段）**
>
> 本节下面"必须放 AXI SRAM / IDMA 看不到 DTCM"的说法，**对现在这份 HAL 不成立**：
> 本工程的 `HAL_SD_ReadBlocks()/HAL_SD_WriteBlocks()` 是 **CPU 读 SDMMC FIFO 的轮询**方式
> （`Drivers/STM32H7xx_HAL_Driver/Src/stm32h7xx_hal_sd.c` 里的 `SDMMC_ReadFIFO` 循环），
> 只有 `HAL_SD_ReadBlocks_DMA()` 才会去写 `IDMABASE0/IDMACTRL`（用 SDMMC 内部 IDMA）。
> 把 `.sd_dma` 放在 AXI SRAM 仍然保留（和 USB 主机缓冲区统一、以后真要换 DMA 方式时不用再改），
> 但**它不是"读卡失败"的原因**：屏幕上如果是 `SD 读卡失败 2xx`（数据阶段），
> 要去查 DAT0/CMD 的接触、线长、卡本身，以及**板载 WIFI 和 TF 卡座共用 SDMMC1**这几件事。
> 排查方法见文末"八、2026-10-05 改动"。


SDMMC1 的扇区读写用的是 `HAL_SD_ReadBlocks()` / `HAL_SD_WriteBlocks()`**轮询方式**，
CPU 自己搬 SDMMC 的 FIFO，**不走 SDMMC 内部 IDMA**。

本工程的 LCD 打开了 D-Cache，用 DMA 就必须处理缓存一致性（Clean / Invalidate）；
轮询方式没有这个问题：缓冲区不用特殊对齐，也不需要维护缓存 —— 少一个坑。
10Hz 记录的数据量（每秒几十字节）用轮询完全够，而且缓冲区都在 DTCM 里（TCM 不被 Cache）。

### 还想用电脑发指令（校准等）怎么办

现在唯一的串口被模块占了，电脑命令没法进来。要用的话，两种办法：

1. 再加一路串口（比如把某路 UART 配到别的引脚）专门接电脑，在
   `HAL_UART_RxCpltCallback()` 里加回命令解析，再补上执行命令的 `CmdProcess()`；
2. 或者校准用手机 App / 上位机单独做一次（模块会把设置存在自己里面）。

## 七、其它注意事项

* **源码编码**：本工程带中文注释的 `.c/.h` 是 **GBK** 编码（Keil ARMCC v5 按 GBK 解析），
  Markdown 文档是 UTF-8。用别的编辑器改 `.c/.h` 后请按 GBK/ANSI 保存，
  否则会报 `invalid multibyte character sequence` 之类。
* **Flash 只剩约 48KB**：以后再加功能要留意（H750XB 片内只有 128KB Flash）。
* **SD 卡带电拔插**：拔卡后程序会报写失败并每 2 秒重试；建议先断电再拔卡，避免数据损坏。
* **数据量**：20Hz、一行约 90 字节 → 约 **6.5MB/小时**，8GB 卡能存上千小时。

### 8.1 屏幕上会看到什么（按这个顺序看就能定位）

| 屏幕提示 | 含义 | 下一步 |
| --- | --- | --- |

实测 `SD 1B202 4B202`：**1 线和 4 线都读不出来**（两个都是"数据阶段 + 数据 CRC 错"）。
说明这**不是**"卡停在 4 线"这一类单一原因，而是 **4 条数据线上的数据都不对**
（命令线 CMD/CK 是好的，所以卡能认出来、不会报"认不到卡"）。结合更早看到的
`0:000002`（有数据、内容不对、也不是悬空的 FFFFFF）：卡在发数据，只是主机收到的位不对 ——
典型就是"数据线上另一个器件在拉/争用"或"卡/卡座的数据脚接触不良"。

v7 做了两件事（软件侧能做的最后一步）：

1. `HAL_SD_MspInit()` 里把 **PC2（WIFI 模块 WL_REG_ON）拉低**，让板载 WIFI 芯片（AP6181）
   一直处于复位状态、引脚高阻。TF 卡座和 WIFI 共用同一组 SDIO 线，WIFI 芯片只要在线上
   加载/驱动，就正好表现为"命令通、数据 CRC 错"。（PC2 在本工程没有别的用途。）
2. 失败时恢复显示"收到的前 3 字节"，并在末尾加一个字符：
   * `=` 两次裸读收到的字节完全一样（稳定 → 系统性错位 / 硬件状态问题）
   * `*` 两次不一样（不稳定 → 接触不良 / 干扰那类问题）

1. **换一张卡**（先在电脑上确认能读）—— 卡本身坏了完全符合现在这个现象；
2. 通电插卡，**用手指按住 / 轻轻晃动卡**，看提示会不会变（会变 = 卡座接触不良 / 虚焊）；
3. **J66 跳线装 / 拔两种状态**各试一次（拔插前先断电）；
4. 万用表量 TF 座 DAT0~DAT3 对 GND 的空闲电压（正常都是 3.3V；某根明显低就是被拉住了）。


实测现象：**命令全通、`202`（数据 CRC 错）、`0:000002`** —— 说明 DAT0 并没有断（数据收到了，
不是悬空的 `FFFFFF`），而是"收到的内容系统性不对"。最典型的原因就是
**卡还在 4 线模式、主机却按 1 线读**：4 线模式下每个字节被拆成两个半字节分散在 DAT3~DAT0 上，
主机只采 DAT0 就会把数据拼错，CRC 必然对不上，而且**和时钟快慢无关**（200kHz 也一样错）。

为什么这个状态一直没能被自动纠正：HAL 里"把卡切回 1 线"要调用
`HAL_SD_ConfigWideBusOperation()`，而它**第一步是读卡的 SCR（一次数据读）**；
数据读一失败（202），它就直接返回错误，**后面的 CMD55 + ACMD6 根本不会发出去** ——
于是卡停在 4 线、主机还是 1 线，怎么重试都没用。

所以 v6 里改成：

1. 先用当前总线宽度（1 线）裸读 0 号扇区；
2. 读失败 → 用新增的 `SD_TryBusWide()` **绕开 SCR** 直接发 `CMD55 + ACMD6(2)` 并把
   `CLKCR.WIDBUS` 改成 4 线，再读一次；
3. **哪种能读就用哪种**（4 线能读就继续用 4 线跑记录）；两种都不行才报错。

屏幕提示格式也随之改成一次显示两个错误码：

```
SD 1B<1线错误码> 4B<4线错误码> 0:<收到的前 3 字节>
例：SD 1B202 4B202 0:000002        两种都失败
    SD 1B202 4B0   0:000002        （不会出现这种，4 线能读就不再报错）
```

读法：

| 显示 | 含义 |
| --- | --- |
| 只剩 `已存 N 帧` | 一切正常（很可能就是 4 线能读，自愈成功） |
| `4B202` / `4B208` | 4 线也读不出来 → 大概率是这条总线被别的器件拉着（先拔 `J66`/拆 WIFI 模块） |
| `0:FFFFFF` | DAT0 一直被拉高（断线/接触不良/被拉载） |
| `0:000002` 这类 | DAT0 有信号但内容不对：位被吃掉/总线争用（WIFI 挂在同一组线上最常见） |
| `0:EB3C90` | 读是好的，问题在文件系统 |

开启第一行会显示 **`USBLOG v6 SD-FIX`**（串口版是 `SDLOG v6 SD-FIX`），用来确认烧的确实是这一版。


`202` = 百位 `2`（**数据阶段**）+ 后两位 `02`（HAL 的 `SDMMC_ERROR_DATA_CRC_FAIL`，**数据 CRC 错**）。

含义：卡的命令全通（CMD0/CMD8/ACMD41/CMD2/CMD3/CMD9/CMD7/CMD16 都成功，所以"卡认得到"），
但主机从 **DAT0** 上收到的 512 字节数据和卡附带的 CRC 对不上 —— 也就是 **DAT0 这一路的电气不对**。
典型原因：DAT0 断线 / 卡座接触不良 / 被同一条线上的另一个器件拉载。板载 WIFI 模块（AP6181）
就挂在同一组 SDIO 线上（含 DAT0 = PC8），所以"WIFI 模块通电"是这块板上最常见的元凶。

新版固件在**读失败时也会**把"收到的前 3 个字节"显示在提示后面，形如 `SD 读卡失败 202 0:FFFFFF`：

| 显示 | 含义 |
| --- | --- |
| `0:FFFFFF` | DAT0 一直被拉高 —— 线断 / 接触不良 / 被别的器件拉载（最常见） |
| `0:000000` | DAT0 一直被拉低 |
| `0:A5A5A5` | 这次连数据阶段都没进去（命令阶段就失败了） |
| 其它值 | 收到数据了，但内容/CRC 不对（信号质量、位对齐问题） |
| `0:EB3C90` | 读是好的（FAT16/32 引导扇区），问题在文件系统 |

对应要查的硬件（按顺序）：

1. 断电 → 拔掉 `J66`（3V3_WIFI）或拆掉板载 WIFI 模块 → 重新上电插卡；
2. 换一张卡（电脑上能读、FAT32 单分区；卡插到底）；
3. 万用表通断：TF 座 **DAT0** ↔ 排针 **PC8**（CMD/CLK 肯定是通的，因为认卡都过了，
   所以重点只查 DAT0 这一根）；
4. 擦一下卡和卡座的触点再试。

> 说明：V1.0 与 V1.1 两版底板原理图的 TF 座引脚是一样的
> （DAT0=PC8、DAT1=PC9、DAT2=PC10、DAT3=PC11、CK=PC12、CMD=PD2，每条线都有 10K 上拉），
> 所以不需要怀疑板子版本差异。


底板原理图（V1.1）页 6/页 8 的原话是"**与TF卡共用SDIO接口，因此WIFI跟TF卡不能同时使用**"：
`PC8/PC9/PC10/PC11/PC12/PD2` 上同时挂着 TF 卡座（J28）和板载 WIFI 模块（U10 = AP6181，
由 `J66` 供 3V3_WIFI，`PC2` = WL_REG_ON）。只要 WIFI 模块在板上且被供电/使能，SDIO 总线上
就多一个设备，SD 卡初始化时会应答冲突 —— **换任何卡都认不到**。

所以"怎么都读不出来"时先做这一件事：**断电 → 拔掉 J66（3V3_WIFI）跳线（或确认没装 WIFI 模块）
→ 重新上电插卡**。
